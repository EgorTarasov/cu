# Changelog

Все изменения проекта документируются в этом файле.

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версионирование —
[SemVer](https://semver.org/lang/ru/).

Раздел `[Unreleased]` накапливает изменения, которые попадут в следующий релиз.
При публикации тега workflow `release.yml` берёт его содержимое как тело релиза,
после чего автоматически переименовывает раздел в `[<version>] - <date>` и
создаёт новый пустой `[Unreleased]` сверху.

## [0.1.9] - 2026-09-04

### Added
- **`install.sh` сам настраивает PATH.** Установка стала действительно
  «одной командой»: скрипт определяет оболочку по `$SHELL` и дописывает
  `export PATH="<dir>:$PATH"` в `~/.zshrc`, `~/.bash_profile` (bash на macOS —
  login shell), `~/.bashrc` или `~/.config/fish/config.fish` (`fish_add_path`).
  Блок помечен `# added by cuni installer` и не дублируется при повторном
  запуске. Отключение — `CU_NO_MODIFY_PATH=1`, тогда строка просто печатается.
- **E2E-тест установщика.** `make test-install` собирает релизный архив из
  текущих исходников, раздаёт его по localhost и прогоняет настоящий
  `install.sh`: проверяет установку, запуск бинаря, отсутствие системной
  утилиты с тем же именем, порядок `PATH` в подсказке и отказ при
  несовпадении контрольной суммы. Сети и опубликованного релиза не требует;
  в CI гоняется на macOS и Linux.
- **Выбор способа входа.** При первом `cuni login` cu спрашивает, как получать
  cookie: вручную (по умолчанию) или через браузер. Выбор сохраняется в
  `~/.cu-cli/config.json`, меняется через `cuni login --setup`, разово
  переопределяется флагами `--manual` / `--browser`. В неинтерактивном
  терминале вопрос не задаётся — используется ручной способ с подсказкой
  про `CU_BFF_COOKIE`.
- **Ручной ввод cookie.** `cuni login --manual` печатает пошаговую инструкцию,
  где взять `bff.cookie` в DevTools, читает значение со скрытым вводом,
  проверяет его через `GET /api/account/me` и сохраняет. Chrome не нужен.
- **Загрузка Chrome по требованию.** Если для входа через браузер Chrome не
  найден, cu предлагает скачать Chrome for Testing (~170 МБ) в
  `~/.cu-cli/chrome`. Загрузка опциональная, только с доверенных хостов
  Google, с защитой от path traversal при распаковке.
- `cuni deadlines` и `cuni grades <курс>` теперь печатают ID задачи (`#1536681`)
  рядом с названием, а в конце — подсказку `cuni task <id> for details`.
  Раньше `cuni task` было невозможно вызвать: хелп отправлял за ID в эти две
  команды, но ни одна его не показывала. То же исправлено в MCP — у тулов
  `list_deadlines` и `get_grades` появилась колонка `Task ID`, без которой
  `get_task` был недостижим и для LLM.

### Changed
- **BREAKING: бинарь переименован `cu` → `cuni`.** На macOS `/usr/bin/cu` —
  системная утилита UUCP (`cu(1)`, «Call up another system»), она есть на
  каждом Маке. При этом `install.sh` советовал *добавлять* `~/.local/bin`
  в конец `PATH`, где `/usr/bin` идёт раньше, — на чистой macOS команда `cu`
  вела на UUCP, а не на наш CLI. Обновите вызовы: `cu login` → `cuni login`.
  Для MCP-хостов переименуйте сервер: `claude mcp remove cu` и заново
  добавьте как `cuni`. Файлы в `~/.cu-cli/` (cookie, настройки) не тронуты —
  переустанавливать доступ не нужно.
- `install.sh` теперь советует `export PATH="<dir>:$PATH"` (в начало, не в
  конец) и предупреждает, если на `PATH` раньше встречается другой бинарь
  с тем же именем.
- **Ручной способ входа стал основным**, вход через браузер — второй вариант.
  Причина: `bff.cookie` выдаёт браузерная сессия, и ручной способ работает
  без Chrome, в том числе на серверах без графики.
- Поиск Chrome теперь общий для всех входов (LMS, GitLab, time.cu.ru, Ktalk):
  `CHROME_PATH` → стандартные пути → `PATH` → скачанная сборка.
- CLI больше не ждёт отправку телеметрии перед выходом. Раньше
  `PersistentPostRun` синхронно дожидался POST в clickstream — это отдельный
  хост со своим TLS-хендшейком, ~500 мс на каждой команде (у `cuni version`,
  который вообще не ходит в LMS, это было 650 из 670 мс). Теперь событие
  дописывается в `~/.cu-cli/telemetry-queue.jsonl`, а очередь разгребается
  фоном на старте следующего запуска, параллельно его работе. Замеры:
  `cuni version` 670 → 20 мс, `cuni task <id>` ~1500 → ~950 мс,
  `cuni courses` ~2000 → ~950 мс. Очередь ограничена 100 событиями,
  отправка идёт не более 20 за запуск; при недоступном эндпоинте события
  сохраняются до следующего раза, а не теряются. MCP не затронут — там
  `Flush` и раньше вызывался один раз за сессию, а не на каждый вызов тула.

### Fixed
- Имена событий телеметрии больше не зависят от имени бинаря: раньше префикс
  срезался literal-строкой `"cu"`, из-за чего после переименования события
  стали бы `command_ni_*`.
- `cuni login` больше не печатает «Cookie validated successfully», не выполнив
  проверку: cookie реально проверяется через API, и при ошибке выводится
  предупреждение.
- Команды `courses`, `deadlines`, `grades`, `materials` при ошибке завершаются
  с кодом `1`, а не `0`. Раньше они печатали ошибку и выходили успешно, из-за
  чего `cuni deadlines || echo fail` молчал. `cuni courses` вдобавок писал
  текст ошибки в stdout — он попадал в файл при перенаправлении вывода.
- Провалы этих команд и протухший cookie снова попадают в телеметрию: раньше
  они шли мимо `reportCommandFailure` и записывались как успешные.
- Подсказки после переименования `cu` → `cuni` больше не отправляют к старому
  имени: `cuni version` печатал `cu 0.1.5`, а `cuni login` советовал
  `cu login --setup` / `cu login --manual`. На macOS `cu` — это системный
  UUCP, то есть подсказки вели мимо CLI.
- В `cuni grades <курс>` выровнена колонка баллов: у заданий с `MaxScore`
  из одной цифры (`0/7`) строка съезжала относительно остальных.

## [0.1.5] - 2026-07-08

> **Примечание для пользователей с v0.1.2 и старше.** Релиз `v0.1.3` был
> опубликован на GitHub без бинарных артефактов (GoReleaser не отработал),
> поэтому все его изменения по факту впервые доезжают до пользователей
> именно в этом релизе. Соответствующая секция `[0.1.3]` ниже остаётся как
> исторический референс — функциональность из неё уже включена.

### Added
- **Анонимная телеметрия использования.** CLI и MCP-сервер отправляют события
  использования (команды, вызовы MCP-тулов с номером в сессии, длительности,
  ошибки — без значений аргументов и личных данных) на self-hosted OpenPanel.
  Устройство идентифицируется случайным ID в `~/.cu-cli/device-id`; MCP-сессии
  получают случайный `session_id` для анализа паттернов вызова тулов.
  Отключение — `CU_NO_TELEMETRY=1`. Креды вшиваются на этапе сборки
  (`make embed-env` из `.env` или секретов CI); сборка без них даёт бинарь
  с полностью выключенной телеметрией.
- **Архивные курсы.** `cuni courses`, `cuni fetch courses`, `cuni show` и MCP-тулы
  `list_courses` / `search_courses` теперь возвращают активные и архивные
  курсы отдельными секциями с пометкой статуса. Архивные тянутся через
  `/api/micro-lms/courses/student?state=archived`. `cuni show` дополнительно
  принимает numeric `course-id` (раньше работал только fuzzy-поиск по имени).
- **Авто-проверка обновлений.** После каждой команды `cuni` раз в 7 дней
  запрашивает последний релиз с GitHub и печатает в stderr подсказку, если
  установленная версия отстаёт. Состояние кэшируется в
  `~/.cu-cli/update-check`; сборки с `version == "dev"` пропускают проверку.
  Сетевой запрос с 3-секундным таймаутом, любые ошибки — silent (не мешают
  основной команде).

### Changed
- `ResolveCourse` (по имени/ID) теперь ищет как среди активных, так и среди
  архивных курсов — раньше архивные были невидимы и обращаться к ним
  приходилось только по numeric ID через `get_course_summary` /
  `get_course_structure`.
- `api-spec.yaml`: у `GET /micro-lms/courses/student` явно описан
  `state=archived` (плюс `offset`); у `/courses/{id}/overview` отмечено, что
  путь общий для активных и архивных курсов.

### Fixed
- Подавление `gosec G101` для трёх env-констант (`CU_MM_TOKEN`,
  `CU_KTALK_NG_TOKEN`, `CU_KTALK_SESSION_TOKEN`) переведено на формат
  `// #nosec G101 ...`, чтобы standalone-gosec в CI тоже признавал
  директиву (golangci-lint видел её и раньше).

## [0.1.3] - 2026-05-17

### Added
- Установочный скрипт `install.sh` для macOS и Linux (Ubuntu/Fedora, amd64/arm64).
- Автоматическая публикация релизов через GoReleaser в `.github/workflows/release.yml`.
- Пакет `internal/render` — общие writer-хелперы для plain/markdown вывода
  (первый шаг к Renderer/Presenter паттерну).
- Авторизация в `time.cu.ru` через браузер: `cuni login --time`
  ловит cookie `MMAUTHTOKEN` и сохраняет в `~/.cu-cli/mm-cookie`.
- Команды `cuni time sync` и `cuni time posts` — инкрементальный pull сообщений от
  `@cu_notification_bot` в локальный JSONL-сторадж
  (`~/.cu-cli/mm/<channel-id>/posts.jsonl`). Настройки через env
  `CU_MM_BASE_URL`, `CU_MM_TEAM`, `CU_MM_BOT_USERNAME`, `CU_MM_TOKEN`.
  Алиас `cu mm ...` сохранён.
- Команда `cuni time recordings [query]` — поиск записей занятий по предмету в
  локальном сторадже с интерактивным выбором, флаг `--all` для печати всех
  совпадений. Парсер живёт в `internal/usecase/recordings` и доступен другим
  фичам (например, для обогащения сводок курсов) через `UseCase.ForCourse`.
- Авторизация в Ktalk (`centraluniversity.ktalk.ru`) через браузер:
  `cuni login --ktalk` ловит cookie `ngtoken`/`kontur_ngtoken` плюс
  localStorage/sessionStorage и сохраняет в `~/.cu-cli/ktalk-tokens.json`.
- Команда `cuni time notifications` — извлекает из бот-сообщений ссылки на новые
  задачи и оценки, индексирует по `course_id`/`longread_id` и печатает
  пары `LMS-ссылка` + `time-permalink`. Фильтры `--course`, `--longread`.
- `cuni time recordings` теперь печатает permalink на исходное time-сообщение
  рядом с ссылками на запись (поле `PostURL` у `Recording`).
- Команда `cuni show [query]` — интерактивный поиск курса (fuzzy по словам)
  и печать полного дерева тем/лонгридов. Если настроен time.cu.ru, к курсу
  подмешиваются записи занятий, а к каждому лонгриду — permalink-и на
  сообщения бота в чате.

### Changed
- Сборка теперь упакована в `tar.gz`/`zip` со списком файлов (бинарь, README,
  CHANGELOG, LICENSE) и единым `checksums.txt`.
- Внутренний пакет `internal/gateway/mm` переименован в
  `internal/gateway/timeclient`. Внешние пути файлов (`~/.cu-cli/mm-cookie`,
  `~/.cu-cli/mm/<channel>/`) и env-переменные `CU_MM_*` оставлены без изменений,
  поэтому уже залогиненная сессия и synced storage продолжают работать.
