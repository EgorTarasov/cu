# cuni login

Сохраняет cookie доступа к LMS, чтобы остальные команды могли им пользоваться.

Есть два способа получить cookie. При первом запуске `cuni login` спросит, какой
вам удобнее, и запомнит выбор в `~/.cu-cli/config.json`.

| Способ | Что нужно | Когда выбирать |
|--------|-----------|----------------|
| **Ручной** (по умолчанию) | Ничего | Вы уже вошли в LMS в браузере. Работает везде, в том числе на серверах без графики |
| **Через браузер** | Google Chrome | Хочется, чтобы cuni всё сделал сам |

## Использование

```bash
cuni login              # способ из настроек (при первом запуске — вопрос)
cuni login --manual     # разово: вставить cookie вручную
cuni login --browser    # разово: открыть Chrome
cuni login --setup      # заново выбрать способ по умолчанию
cuni login --timeout 10m
```

## Флаги

| Флаг | По умолчанию | Описание |
|------|--------------|----------|
| `--manual` | `false` | Вставить cookie вручную |
| `--browser` | `false` | Забрать cookie через Chrome |
| `--setup` | `false` | Заново задать вопрос о способе входа |
| `--timeout` | `5m` | Таймаут ожидания входа в браузере |
| `--gitlab` | `false` | Вход в git.culab.ru |
| `--time` | `false` | Вход в time.cu.ru |
| `--ktalk` | `false` | Вход в centraluniversity.ktalk.ru |

## Способ 1 — вручную

Как достать `bff.cookie` из браузера:

1. Откройте <https://my.centraluniversity.ru> и войдите в аккаунт.
2. Откройте DevTools:
   - macOS — <kbd>Cmd</kbd>+<kbd>Option</kbd>+<kbd>I</kbd>
   - Windows / Linux — <kbd>F12</kbd> или <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>I</kbd>
3. Перейдите на вкладку **Application** (Chrome, Edge) или **Storage** (Firefox).
4. Слева выберите **Cookies** → `https://my.centraluniversity.ru`.
5. Найдите строку `bff.cookie` и скопируйте её значение из колонки **Value**.

Затем выполните `cuni login --manual` и вставьте значение. Ввод скрыт, чтобы
cookie не остался в истории терминала. cuni сразу проверит его через
`GET /api/account/me` и сохранит в `~/.cu-cli/cookie` (права `0600`).

Значение длинное — копируйте целиком, без кавычек. Если случайно скопировали
вместе с именем (`bff.cookie=...`), префикс будет отброшен автоматически.

## Способ 2 — через браузер

```bash
cuni login --browser
```

1. cuni ищет Chrome: переменная `CHROME_PATH`, стандартные пути установки, `PATH`.
2. Если Chrome не найден — предложит скачать Chrome for Testing (~170 МБ)
   в `~/.cu-cli/chrome`. Отдельная сборка используется только для входа и
   не трогает ваш обычный браузер и его профиль.
3. Открывается окно, вы входите через Keycloak SSO.
4. cuni забирает `bff.cookie` и сохраняет его.

Отказаться от загрузки можно в любой момент — тогда установите Chrome сами,
укажите путь через `CHROME_PATH` или используйте ручной способ.

## Переменные окружения

```bash
export CU_BFF_COOKIE="значение-cookie"   # приоритетнее сохранённого файла
export CHROME_PATH="/path/to/chrome"     # какой Chrome запускать
```

`CU_BFF_COOKIE` удобен в CI и на серверах: `cuni login` там не нужен вовсе.

## Как это работает

`bff.cookie` — это серверная сессия LMS (паттерн Backend-For-Frontend), а не
OAuth-токен. Получить её можно только из браузера, где вы прошли вход, поэтому
оба способа сводятся к «забрать cookie у браузера»: вручную или через CDP.

Все последующие команды используют сохранённый cookie и проверяют его перед
каждым запросом. Если cookie истёк — выполните `cuni login` ещё раз.

Схема жизненного цикла cookie: [`diagrams/auth-cookie-lifecycle.html`](diagrams/auth-cookie-lifecycle.html).

## Другие сервисы

`--gitlab`, `--time` и `--ktalk` всегда используют браузер — там нужен полный
SSO-редирект, который вручную не воспроизвести. Chrome для них ищется и
скачивается так же, как описано выше.
